## 📑 프로젝트 규칙

### 🌿 브랜치 규칙

|    종류     | 설명                 | 예시                | 비고               |
| :---------: | :------------------- | :------------------ | :----------------- |
|  **main**   | 메인 브랜치          | `main`              | 그대로 사용        |
|   **dev**   | 배포 전 개발 브랜치  | `develop`           | 그대로 사용        |
| **feature** | 기능 개발 브랜치     | `feature/10—signin` | 로그인 기능 브랜치 |
| **hotfix**  | 디버깅 브랜치        | `hotfix-1.1.4`      | 1.1버전 디버깅     |
| **release** | 배포하기 위한 브랜치 | `release-1.1`       | 1.1 버전           |

**타입/이슈번호—작업-내용**

- e.g. `feature/7—button-component`

### 🌿 커밋 메세지 규칙

- **타입: 제목 (이슈번호)**
  - e.g. `feat: 메인 페이지 구현 (#5)`
  - (한 줄 띄움)
  - `- 구현 내용 1`
  - `- 구현 내용 2`

|     Type     | 설명                                                 |
| :----------: | :--------------------------------------------------- |
|   **feat**   | 새로운 기능 추가                                     |
|   **fix**    | 버그 수정                                            |
| **refactor** | 리팩토링                                             |
|  **design**  | CSS 및 사용자 UI 디자인 변경                         |
|  **style**   | 코드 포맷팅, 세미콜론 누락, 코드 변경이 없는 경우    |
|   **test**   | 테스트(테스트 코드 추가, 수정, 삭제)                 |
|  **chore**   | 기타 변경사항 (빌드 스크립트 수정, 패키지 매니저 등) |
|   **init**   | 프로젝트 초기 생성                                   |
|  **rename**  | 파일 혹은 폴더명 수정 또는 이동                      |
|  **remove**  | 파일을 삭제하는 작업만 수행한 경우                   |
|   **type**   | 타입 정의                                            |

### 🌿 이슈 및 PR 라벨

- **Feature** - 기능 구현
- **Bug** - 버그 관련
- **Refactor** - 코드 리팩토링
- **Setting** - 개발 환경 세팅
- **Docs** - 문서 작성 및 수정
- **Design** - 마크업 및 스타일링
- **Deploy** - 배포
- **Rename** - 파일명 수정 혹은 파일 위치 이동

### 🌿 파일/폴더 이름

- 컴포넌트 파일의 경우 **PascalCase.tsx** 로 작성한다.
  - e.g. `PillList.tsx`
- 커스텀 훅 파일의 경우 **camelCase.ts** 로 작성한다.
  - e.g. `useDebounce.ts`
- 모든 폴더와 위 2가지 경우를 제외한 파일의 경우 **kebab-case** 로 작성한다.
  - e.g. `/common-components`, `api-response-types.ts`

### 🌿 import문

- **import** 문은 반드시 **절대경로**로 작성한다.

### 🌿 변수 네이밍

- 약어 사용은 지양한다.

### 🌿 Lucide Icon

- 아이콘 이름 뒤에는 항상 **Icon**을 붙인다.

### 🌿 React Router

- React router 관련 import시 “react-router-dom”이 아니라 “react-router”에서 import

### 🌿 MSW

- 폴더구조

1. 더미데이터는 mocks/data 폴더 아래에 파일을 만들어 관리한다.

2. handler는 mocks/handlers 폴더 아래에 파일을 만들어 관리한다.
   a. 기능별로 파일 분리
   b. 파일 안에 너무 많아지면 추가로 분리

3. 개별 핸들러를 export 하지 않고 핸들러 배열을 만들어 해당 배열을 export 한다.

### 🌿 Tanstack query

1. useQuery를 상위 컴포넌트에서 바로 사용하지 않고 별도 훅으로 관리한다.
2. 훅은 hooks/api 폴더 내에 별도 파일로 관리한다.
3. 훅은 useQuery가 반환하는 객체 그대로 반환한다.
4. 상위 컴포넌트에서 옵션을 변경할 수 있도록 options 파라미터를 사용한다
